# pull.php

**Автодеплой с GitHub на хостинг — одним PHP-файлом.**

[English version](README.en.md)

`pull.php` скачивает ZIP-архив выбранной ветки репозитория, распаковывает его и
копирует содержимое нужной папки в тот каталог, где лежит сам скрипт. Ни git,
ни SSH, ни shell-доступа на хостинге не требуется — достаточно PHP и обычного
исходящего HTTPS.

---

## Зачем это нужно

### Проблема

Код живёт в GitHub, а сайт — на дешёвом shared-хостинге, где из инструментов
только FTP и панель управления. Между ними — ручной перенос файлов, и он
ломается предсказуемо:

- залили не все файлы — на проде «половина фичи»;
- залили поверх старую версию — откат непонятно куда;
- никто не знает, что именно сейчас лежит на сервере: состояние прода не
  совпадает ни с одним коммитом;
- удалённые из репозитория файлы годами остаются на сервере — старые скрипты,
  забытые бэкапы, мусор, который иногда ещё и доступен по прямой ссылке;
- обновить сайт может только тот, у кого настроен FTP-клиент.

Нормальный CI/CD это решает, но на лендинг или сайт-визитку заводить GitHub
Actions с FTP-деплоем, хранить секреты и отлаживать пайплайн — дороже самой
задачи. А `git pull` по SSH недоступен: на таком хостинге нет ни SSH, ни git.

### Решение

Один файл, который кладётся в каталог сайта и делает деплой по открытию
ссылки. Состояние сервера становится копией ветки в GitHub — с включённым
режимом зеркала буквально точной копией, без накопленного мусора.

### Для кого

- **Фрилансеры и веб-студии**, которые сдают сайты на клиентский shared-хостинг
  (Beget, Timeweb, reg.ru, SpaceWeb и подобные) без SSH.
- **Небольшие команды** с лендингами, визитками, статикой и простыми
  PHP-сайтами, где полноценный CI избыточен.
- **Владелец сайта или контент-менеджер** — обновление сайта превращается в
  «открыть ссылку и нажать кнопку», без git и без FTP-клиента.
- **Агентства при передаче проекта**: хостинг остаётся у клиента, исходники —
  в GitHub, связь между ними — этот файл.

### Что это даёт

| | Было | Стало |
|---|---|---|
| Выкладка | FTP-клиент, руками, выборочно | открыть URL или строка в cron |
| Источник правды | «что-то лежит на сервере» | ветка в GitHub |
| Мусор от старых версий | копится годами | удаляется автоматически (режим зеркала) |
| Кто может выкатить | у кого настроен FTP | у кого есть пароль от `pull.php` |
| Инфраструктура | — | нет: ни runner'а, ни composer'а, ни зависимостей |
| Настройка | — | форма в браузере при первом открытии |

### Когда не подойдёт

Честные границы применимости:

- **Нужна сборка** (`npm run build`, компиляция ассетов) — скрипт выкладывает
  репозиторий как есть. Вариант: коммитить собранное или собирать в CI и класть
  артефакты в отдельную ветку, а `pull.php` тянуть уже её.
- **Большой репозиторий или частые деплои** — каждый запуск качает архив ветки
  целиком; инкрементальной докачки нет.
- **Нужны атомарность, откат, миграции БД, zero-downtime** — во время
  копирования сайт какое-то время в промежуточном состоянии. Для такого нужен
  Deployer, Capistrano или полноценный CI.
- **На хостинге есть SSH и git** — тогда `git pull` проще, быстрее и честнее.

## Как это работает

1. Скачивает архив ветки (по очереди пробуются три источника):
   `api.github.com/repos/…/zipball/…`, `codeload.github.com`,
   `github.com/…/archive/refs/heads/….zip`.
2. Распаковывает во временный каталог (`sys_get_temp_dir()`).
3. Находит внутри архива указанную подпапку (`subdir`).
4. Копирует её содержимое поверх каталога со скриптом, пропуская файлы из
   списка «не трогать».
5. Если включён режим зеркала — удаляет из каталога всё, чего нет в
   репозитории.
6. Удаляет временные файлы и печатает баннер с результатом: статус, время
   старта и финиша, длительность, сколько файлов скопировано и удалено.

## Требования

- PHP 7.4+
- расширение `ZipArchive`
- cURL либо `allow_url_fopen = On`
- исходящий HTTPS к `github.com` / `api.github.com` / `codeload.github.com`
- право на запись в каталог, куда идёт деплой

## Установка

1. Загрузите `pull.php` в тот каталог сайта, содержимое которого нужно
   обновлять (например, в корень или в `public_html/`).
2. Откройте `https://ваш-сайт/pull.php` в браузере.
3. При первом запуске (когда рядом ещё нет `pull-config.php`) откроется форма
   настройки — заполните поля и нажмите «save_config».
4. Скрипт создаст `pull-config.php` (права `0600`) и предложит сразу запустить
   первый деплой.

Дальше любой заход на `pull.php` выполняет деплой.

## Поля формы настройки

| Поле | Значение | Пример |
|---|---|---|
| `repo` | репозиторий в формате `owner/name` | `dansury/pull` |
| `branch` | ветка, из которой тянуть | `main` |
| `subdir` | папка внутри репозитория, содержимое которой раскладывается в каталог скрипта; `.` — весь корень репозитория | `.` или `website/public` |
| `gh_token` | Personal Access Token, **нужен только для приватных репозиториев** | `github_pat_…` |
| `timezone` | IANA-таймзона для отметок времени в баннере | `Europe/Moscow` |
| `keep_files` | имена файлов и папок верхнего уровня, которые нельзя перезаписывать и удалять | `.htaccess, uploads` |
| `password` | пароль на запуск деплоя; пусто — без пароля | `••••••` |
| `purge` | удалять файлы, которых больше нет в репозитории | включено по умолчанию |

`pull.php` и `pull-config.php` сохраняются всегда, независимо от `keep_files`.

## Пароль и «запомнить меня»

URL скрипта запускает деплой, поэтому пароль стоит задать сразу.

- Пароль **хранится хешированным** (`password_hash()`), сам он на диск не
  попадает. Минимальная длина — 6 символов.
- Перед каждым запуском показывается экран разблокировки с галочкой
  **«remember me on this browser»**:
  - галочка включена — в браузер кладётся подписанная кука на **30 дней**,
    пароль больше не спрашивается;
  - галочка снята — кука сессионная и умирает вместе с браузером (так и стоит
    делать на чужом компьютере).
- Кука не содержит пароль: это срок действия + HMAC-подпись, ключом для которой
  служит сохранённый хеш. Подделать её без доступа к `pull-config.php` нельзя, а
  смена пароля разом обесценивает все выданные ранее куки.
- Кука ставится с флагами `HttpOnly`, `SameSite=Lax`, `Secure` (на HTTPS) и
  ограничена каталогом скрипта.
- `pull.php?logout=1` — забыть пароль в этом браузере.

Оставить поле пароля пустым можно — тогда деплой доступен всем, кто знает
адрес; см. раздел «Безопасность».

## Удаление устаревших файлов (режим зеркала)

Опция `purge` — галочка «Delete files that are gone from the repository»,
**включена по умолчанию** для новых установок.

Что делает: после каждого копирования проходит по каталогу и удаляет всё, чего
нет в репозитории. Каталог становится точной копией папки из репозитория.

> ⚠️ **Операция безвозвратна.** Файлы удаляются с диска, корзины нет. Всё, что
> создано на сервере и отсутствует в репозитории — загрузки пользователей,
> кеши, логи, файлы конфигурации — будет удалено, если не внесено в
> `keep_files`.

Что защищает от неприятностей:

- имена из `keep_files` (плюс всегда `pull.php` и `pull-config.php`)
  пропускаются целиком, вместе со всем содержимым, если это папка;
- удаление выполняется **только после успешного копирования** — сорванная
  закачка или битый архив не приводят к удалению;
- символические ссылки не разыменовываются: удаляется сама ссылка, то, на что
  она указывает, не трогается.

Если опция выключена — файлы, удалённые из репозитория, остаются на сервере, и
чистить их нужно вручную.

**Для уже установленных копий:** в старом `pull-config.php` ключа `purge` нет, и
в этом случае режим считается **выключенным** — обновление скрипта само по себе
ничего не удалит. Чтобы включить, добавьте `'purge' => true` в конфиг или
удалите `pull-config.php` и пройдите настройку заново.

## Токен доступа

Для публичного репозитория токен не нужен. Для приватного:

**Fine-grained PAT** (рекомендуется) — `github.com/settings/personal-access-tokens/new`:
Repository access → «Only select repositories» → нужный репозиторий;
Repository permissions → **Contents: Read**.

**Classic PAT** — `github.com/settings/tokens/new`: полный scope `repo`
(именно `repo`, одного `public_repo` для приватного репозитория недостаточно).

Если скачивание отдаёт `404` при заданном токене — у токена нет доступа именно к
этому репозиторию, либо он истёк/отозван. Скрипт выводит эту подсказку сам.

## Файл конфигурации

`pull-config.php` генерируется формой и просто возвращает массив — его можно
править руками:

```php
<?php
return [
    'repo'          => 'owner/name',
    'branch'        => 'main',
    'subdir'        => '.',
    'gh_token'      => '',
    'keep_files'    => ['pull.php', 'pull-config.php', '.htaccess', 'uploads'],
    'timezone'      => 'Europe/Moscow',
    'password_hash' => '',    // хеш пароля; пусто — без пароля
    'purge'         => true,  // удалять файлы, которых нет в репозитории
];
```

Пароль руками в этот файл не вписывают — только хеш. Проще всего задать его
через форму настройки, либо сгенерировать самому:
`php -r "echo password_hash('ваш-пароль', PASSWORD_DEFAULT);"`.

Удалите `pull-config.php`, чтобы заново открыть форму настройки.

## Переменные окружения

Обе необязательны и задаются на стороне хостинга (например, через `.htaccess`
`SetEnv` или панель управления).

| Переменная | Назначение |
|---|---|
| `GITHUB_TOKEN` | токен доступа; **имеет приоритет** над `gh_token` из конфига — удобно, чтобы не хранить секрет в файле |
| `KRASKI_PULL_ALLOW_IPS` | список IP через запятую, которым разрешён запуск. Пусто — разрешено всем, иначе остальные получают `403` |

## Запуск

Из браузера:

```
https://ваш-сайт/pull.php
```

Вывод оформлен как терминал и печатается потоком, по мере выполнения.

Из cron или curl — параметр `?plain=1` отдаёт чистый `text/plain` без разметки,
а пароль передаётся заголовком `X-Pull-Password`:

```bash
curl -s -H "X-Pull-Password: $PULL_PASSWORD" "https://ваш-сайт/pull.php?plain=1"
```

Пример ежедневного деплоя в 4:00 через cron:

```cron
0 4 * * * curl -s -H "X-Pull-Password: пароль" "https://ваш-сайт/pull.php?plain=1" >> /var/log/pull.log 2>&1
```

Пароль принимается и параметром `?password=…`, но так он попадает в логи
веб-сервера и в историю браузера — заголовок надёжнее.

Коды ответа: `200` — успех, `401` — нужен пароль или пароль неверный,
`403` — IP не в списке разрешённых, `502` — не удалось скачать архив,
`500` — ошибка распаковки, отсутствует `ZipArchive`, не найдена подпапка или не
создаётся временный каталог.

## Важные особенности

- **Режим зеркала удаляет безвозвратно.** Всё, что нужно сохранить на сервере,
  должно быть либо в репозитории, либо в `keep_files`.
- **`keep_files` работает только на верхнем уровне.** Вложенные пути
  (`assets/config.json`) не защищаются — внутри подпапок и копируется, и
  удаляется всё.
- **Деплой не атомарный.** Пока идёт копирование, сайт какое-то время находится
  в промежуточном состоянии.
- **Ограничения хостинга.** Скрипт запрашивает `set_time_limit(300)` и ставит
  `ignore_user_abort(true)`, но жёсткие лимиты хостинга могут оборвать
  выполнение на большом репозитории.
- **Токен лежит в файле рядом с сайтом.** Файл создаётся с правами `0600`, но
  надёжнее передавать токен через `GITHUB_TOKEN`.

## Безопасность

`pull.php` доступен всем, кто знает URL. Минимум одно из:

- **задать пароль** при настройке — самый простой вариант;
- задать `KRASKI_PULL_ALLOW_IPS` со списком доверенных адресов;
- закрыть файл HTTP-авторизацией (`.htaccess` + `.htpasswd`);
- переименовать файл в неугадываемое имя (тогда добавьте новое имя в
  `keep_files`, чтобы деплой не затёр сам себя).

Пароль и IP-фильтр можно и нужно сочетать: фильтр отсекает лишние запросы ещё
до проверки пароля.
